# AI編集部 利用ガイドライン

アトミックソフトウェアのAI編集部を claude.ai で使うメンバー向けの説明書です。
企画書の作成から原稿の執筆、校正、最終レビューまでを、チャットだけで進められます。

対象読者: 編集部スキルを有効化された claude.ai アカウントを持つメンバー
管理者: PR担当／高根 千聖

---

## 1. AI編集部とは

記事制作の工程ごとに専門の担当が用意されたAIチームです。担当は次の5役です。

| 担当 | やること | 起動ワード |
|---|---|---|
| 企画担当（カワセミ） | テーマや素材から企画書を作る | 企画よろ |
| ライティング担当（ハシボソカラス） | 企画書と文字起こしから原稿を書く | ライティングよろ |
| エッセイ担当（ウグイス） | 自分の実体験を聞き取って記事にする | エッセイよろ |
| 校正担当（オオタカ） | 原稿の表記や構成をチェックして直す | 校正よろ |
| 最終レビュー担当（シジュウカラ） | 公開前の最終チェックと改善提案 | 最終レビューよろ |

どの担当に頼めばよいか分からないときは「編集部よろ」とだけ送ってください。
受付ディレクター（editor）が選択肢を出して案内します。

## 2. 対応している記事種別

| 種別 | 内容 |
|---|---|
| オウンドメディア インタビュー | note や VerticalSaaS Mag. 向けの取材記事 |
| オウンドメディア 対談 | 話者2名以上が対等に意見を交わす記事 |
| オウンドメディア エッセイ | 書き手の実体験や知見を届ける読み物 |
| 入社エントリ | 語りおろし形式の採用ブランディング記事 |
| プレスリリース | PR TIMES 掲載用のリリース原稿 |
| 導入事例インタビュー | 顧客の導入体験を聞くQ&A記事 |

種別を指定しなくても、依頼内容から自動で判断します。判断に迷う場合は確認の質問が返ってきます。

## 3. はじめかた

1. claude.ai で新しいチャットを開く
2. 「編集部よろ」と送る
3. 表示された選択肢から、やりたいことを番号で答える
4. 案内に従って素材や情報を渡す

スキルが反応しない場合は、claude.ai の設定でスキル「ai-editorial」が有効になっているか確認してください。
見当たらないときは管理者の高根さんに連絡してください。

## 4. 基本のフロー

フルコースで使う場合は、企画から順に進めます。

1. 企画担当（カワセミ）に素材とテーマを渡して企画書を作る
2. 企画書と文字起こしをライティング担当（ハシボソカラス）に渡して原稿を書く
3. 校正担当（オオタカ）が表記と構成をチェックして修正済み原稿を出す
4. 最終レビュー担当（シジュウカラ）が公開前の最終チェックをする

エッセイは工程が違います。取材の文字起こしがなく書き手の実体験だけが素材になるため、
エッセイ担当（ウグイス）がヒアリングから企画、執筆までを一人で担当します。
その後は校正担当（オオタカ）と最終レビュー担当（シジュウカラ）に渡す流れは同じです。

各ステップの成果物の末尾に「次のステップ」の案内が付きます。
そのまま同じチャットで「次お願いします」と送れば続きに進めます。

途中から使ってもかまいません。例、すでに書いた原稿の校正だけを頼む、企画書だけ作るなど。

## 5. 依頼のしかたの例

### 企画書を作りたい

「企画よろ」と送ると次のテンプレが返ってきます。埋めて送り返してください。

```
📝 企画テンプレ（このまま埋めて送り返してください）

・タイトル：
・テーマ：
・読者（ターゲット）：
・読者の読後感・便益：
・ポイントとなる要素：
```

インタビューの文字起こしやヒアリングメモがあれば、一緒に貼り付けるか添付してください。

### 原稿を書いてほしい

「ライティングよろ」に続けて、企画書と文字起こしを渡します。
企画書がない場合はその旨を伝えれば、素材から直接執筆します。

あわせて、参考にするべき情報のURLを渡してください。過去のリリースや記事、
サービスページ、調査データなど、執筆の前提として読んでおくべきものが対象です。
渡さなかった場合はライティング担当（ハシボソカラス）から確認が入ります。

### 原稿を校正してほしい

「校正よろ」に続けて原稿を貼り付けます。指摘一覧と修正済み原稿がセットで返ってきます。

### 公開前の最終チェックをしてほしい

「最終レビューよろ」に続けて原稿を渡します。チェック結果と原稿全文が返ってくるので、
「A. 承認」か「B. 修正指示」で答えてください。

## 6. 品質と表記のルール

AI編集部は、社内の表記レギュレーションを自動で適用します。代表例は次のとおりです。

- プロダクト名は「medicalforce」と「警備フォース」で統一する。medicalforce は小文字始まりの一単語で表記する
- 社名は「アトミックソフトウェア株式会社」。旧社名を現社名として使わない
- 氏名は姓と名の間に半角スペース（例、畠中 翔一）
- 根拠のない誇張表現やAIらしい定型文の禁止

利用者がルールを覚える必要はありません。ただし公開前の最終確認は必ず人間が行ってください。

## 7. 改善要望の出しかた

出来上がった原稿に直したい点があれば、そのままチャットで伝えてください。
その場で修正されるのに加えて、繰り返し起きる指摘は「学習エッセンス提案」として整理されます。

- 学習エッセンス提案が出たら、内容をコピーして管理者の高根さんに共有してください
- スキル本体を編集できるのは管理者だけです。承認された提案だけが次回の更新に反映されます
- 反映されると、チーム全員のAI編集部が同じ改善を受け取ります

## 8. 注意事項

- 未公開の経営情報や顧客の機密は、記事化の承認が取れているものだけを渡してください
- 記事に登場する人物名の公開可否は、事前に本人へ確認してください
- AIの出力をそのまま公開しない。事実関係と固有名詞は必ず人間が確認してください
- 生成された数値や実績は、一次情報と突き合わせてから使ってください

## 9. 困ったときは

| 症状 | 対処 |
|---|---|
| 「編集部よろ」に反応しない | スキル「ai-editorial」の有効化を確認。なければ管理者へ連絡 |
| 期待と違う種別の原稿になった | 記事種別を明示して依頼し直す（例、「エッセイとして書いて」） |
| 表記ルールと違う出力が出た | 該当箇所を指摘すると修正される。繰り返す場合は学習エッセンス提案として管理者へ |
| その他の質問 | 管理者の高根さんへ |
